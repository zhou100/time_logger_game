## Vision

### 10x Check
The landing page IS the product demo. When you land, you see a living week-arc:
someone's open TODOs rolling across Mon–Fri, a recurring theme ("deep work keeps coming
up — 4x this week"), and one coach line. One click signs you in (Google) or one field
(email → 6-digit code, no password). Under 10 seconds from landing to first capture.

### Dream State
Sign-up is solved: Google = one click, email = one field + one code, no password ever.
The only credential users need is their email address. The landing tells the pattern
story, not the daily audit story — showing what Brief notices *across time*, not just today.

## Accepted Scope

- **LandingPage.tsx:** Hero CTA row = "Start your debrief" + "Sign in with Google" side by side.
  Demo section = open loops + recurring themes (week-arc, two-column), not time breakdown + AI audit.
- **Auth flow:** Unified sign-in/sign-up via email → 6-digit OTP (Supabase signInWithOtp).
  Google OAuth as the one-click alternative. No password at all.
- **LoginForm / RegisterForm → unified SignInForm:** Email field → OTP entry → in app.
  No separate login vs. register distinction (Supabase handles new vs. returning user).
- **AuthContext:** New `sendOTP(email)` + `verifyOTP(email, token)`. Remove `register()`.

## Auth Flow State Machine

```
LANDING
  [Sign in with Google] ──────────→ SUPABASE OAUTH ──→ APP
  [Start your debrief]  ──→ SignInForm
                                │
                         [email input]
                                │
                         [sendOTP] ──→ OTP_SENT
                                          │
                                   [6-digit input]
                                   (auto-submit on paste)
                                          │
                                   [verifyOTP] ──→ SUCCESS ──→ APP
                                              ↘ EXPIRED ──→ resend CTA
                                              ↘ INVALID (×3) ──→ "Too many attempts" + resend
                                              ↘ Supabase 429 ──→ "Request a new code"
```

## OTP Frontend Code Pattern

```typescript
// Unified sign-in/sign-up — one call handles both new and returning users
const { error } = await supabase.auth.signInWithOtp({
  email,
  options: { shouldCreateUser: true }  // creates account if not exists
});

// Verify the 6-digit code
const { data, error } = await supabase.auth.verifyOtp({
  email,
  token: otpCode,  // 6-digit string from user
  type: 'email'
});
```

## AuthContext API Signatures

```typescript
sendOTP(email: string): Promise<{ error?: string }>;
verifyOTP(email: string, token: string): Promise<{ error?: string }>;
// Remove: register()
// Keep: loginWithGoogle(), logout(), existing session management
```

## OTP Input UX Spec

- Single 6-digit input field (not 6 individual boxes)
- Auto-focus on mount
- Accept paste from clipboard — auto-submit on full 6-digit detection
- Show digits as typed, no masking (it's a code, not a password)

## Critical Edge Cases

| Case | Behavior |
|------|----------|
| OTP expired | "This code has expired" + "Send a new code" button |
| OTP wrong ×3 | Disable input + "Too many attempts — request a new code" + resend button |
| Supabase 429 | Catch + show "Too many attempts. Please request a new code." |
| Google OAuth | Confirm `REACT_APP_USE_SUPABASE=true` in Render env vars |
| OTP + Google same email | Requires "Link accounts with same email" in Supabase settings (see checklist) |
| Network failure on send | "Couldn't send code — check your connection" + retry button |
| OTP paste | Supported. Auto-submit on full 6-digit paste. |

- **Secondary:** "Start your debrief" — MUI `Button variant="outlined"`, vermilion. Leads to /login (email + OTP path).

### Resend Cooldown Behavior
- After Resend click: button disables for 30s, label becomes "Resend in {N}s..."
- Countdown decrements every second; at 0, label returns to "Resend code" and button re-enables
- Prevents accidental spam; respects Supabase rate limits gracefully

### Responsive Specs
- **Hero CTA row mobile (<600px):** stacked, both buttons full-width, Google on top, 12px gap (sm scale + 4px)
- **Hero CTA row desktop (≥600px):** side-by-side, auto-width, 16px gap (md scale)
- **Demo two-column desktop (≥900px):** `grid-template-columns: 1fr 1.4fr` (DESIGN.md Layout)
- **Demo mobile (<900px):** single column, Open Loops first, Recurring Themes second
- **SignInForm:** always single column, max-width 400px, centered horizontally, mt=8 from top

### Accessibility Specs
- **Focus management:** Step 1 → email field autoFocus. After successful sendOTP, focus moves to OTP input (autoFocus on mount of step 2).
- **Keyboard nav:**
  - Step 1: Tab order = Google → Email → Send button. Enter in email field submits.
  - Step 2: Tab order = OTP input → Resend → "Wrong email?" link. Enter in OTP submits.
- **Touch targets:** All buttons ≥44px height. OTP input ≥48px height.
- **Screen readers:**
  - OTP error messages: `aria-live="polite"` on the helper-text container so errors are announced.
  - OTP input: `aria-describedby` linked to the helper text ("We sent a code to you@example.com").
  - Resend cooldown: `aria-live="polite"` so screen readers hear "Resend in 25 seconds".
- **Color contrast:** All text passes WCAG AA against cream paper #F5EDE0 (text-primary #201815 = ~16:1).
- **Reduced motion:** Honor `prefers-reduced-motion` (no Resend countdown animation; static label updates only).
