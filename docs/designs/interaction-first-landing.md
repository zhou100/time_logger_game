## Vision

### 10x Check

The landing IS the product. A visitor taps a big mic on the page, says one thing in
their own voice, and gets back a real structured debrief (summary + key points + todos)
within seconds — without ever seeing an auth screen. Sign-in is not a gate; it is a
save action that appears *after* the product has already demonstrated value.

The 10x unlock is the **anonymous flywheel**: if a visitor records again (same browser,
same cookie), and again, we start surfacing a teaser pattern — "you've mentioned focus
twice today" — that requires sign-in to see in full. Auth is earned by the product, not
demanded.

### Platonic Ideal

A visitor in a coffee shop, 30 seconds. Taps the page. Taps the mic. Says "I keep
getting distracted today and I don't know why." Gets back an 8-second debrief. Reads it.
Thinks *"huh, that's actually kind of true."* Taps sign-in with Google. Lands in /welcome
with their debrief already saved. Total time to activation: under a minute. No form, no
password, no waiting. The feeling is not "I signed up for an app" — it is *"I used a
thing that understood me and now I want to keep it."*

## Accepted Scope (added to this plan)

- Landing page: Hero with minimal top nav (Logo left only — **no top-nav Sign in link**,
  auth lives only in the footer to keep "interaction-first" coherent). Hero headline
  "Debrief your day.", subtitle "Speak your day. Get a clear summary, key points, and
  todos.", large mic button "Tap to speak" with "No sign-in required" label, "Try saying"
  example prompts below mic, fake "What your debrief looks like" strip showing example
  Summary / Key Points / Todos output (doubles as skeleton visible *during* Whisper+LLM
  latency so the user has something to read). Auth footer "Keep your history across devices"
  with Google + magic link. Small PII disclosure line under mic: "Recordings are deleted
  after 24h unless you save them." + link to /privacy.
- Backend: new public endpoints `POST /v1/public/demo/presign` and `POST /v1/public/demo/submit`.
  Presign response includes a token-bound short-lived PUT URL to MinIO with a narrowed key
  prefix (`anonymous-demo/{demo_session_id}/`), CORS allowing the landing origin only,
  Content-Type pinned to `audio/webm`. Turnstile verification applied to BOTH /presign and
  /submit to prevent presign-URL spam.
- New `anonymous_demo_entries` Postgres table: `id`, `demo_session_id`, `audio_key`,
  `transcript`, `summary`, `key_points` JSONB, `todos` JSONB, `created_at`, `expires_at`
  (created_at + 24h). **MinIO blobs MUST be deleted alongside rows** — TTL sweep job
  (APScheduler or cron on backend) runs hourly, deletes rows where `expires_at < now()`
  and issues `DELETE` on their MinIO keys.
- Turnstile verification: server-side verify against Cloudflare; on failure,
  return HTTP 400 with `{"error": "verification_failed"}` — frontend re-renders Turnstile
  challenge widget inline. Never fail silently.
- Rate limits (SlowAPI): **5 requests / IP / minute** and **3 successful submissions /
  demo_session_id / hour** and **10 successful submissions / IP / 24h**. All limits keyed
  on hashed IP (SHA-256 of `X-Forwarded-For` + env `DEMO_IP_HASH_SALT`, rotated quarterly).
- **Daily OpenAI cost cap:** env `DAILY_DEMO_OPENAI_USD_CAP` (default $5 for launch).
  Tracked in a single-row `demo_cost_counter` table keyed by UTC date, incremented with
  `SELECT ... FOR UPDATE` to avoid concurrent overshoot. When tripped, `/submit` returns
  `{"demo": "capped", "fake_output": {...}}` and the frontend shows the pre-baked fake
  debrief with a banner "Demo is resting — sign in to try yours." Reset at UTC midnight
  via sweep job.
- **Minimal abuse log:** one row per `/submit` call in `demo_request_log` with hashed IP,
  demo_session_id, outcome (`ok|turnstile_failed|rate_limited|capped|error`), whisper_ms,
  total_cost_usd, timestamp. Retained 14 days then pruned.
- **Demo session cookie:** name `tlg_demo_sid`, 64-char random, `SameSite=Lax`
  (required so the cookie survives the Google OAuth top-level redirect), `Secure` in
  prod, **NOT `HttpOnly`** (frontend needs to read it for PostHog event attribution and
  to pass to `/claim-demo-session`), `Max-Age=86400` (24h). Set by the first mic tap.
- Merge flow: `POST /v1/entries/claim-demo-session` (auth required). Body:
  `{ demo_session_id: string }`. Behavior:
  - **Missing / unknown / expired session:** return `{ claimed: 0 }` + analytics event
    `demo_claim_missing`. Silent no-op by design.
  - **Rows found:** within a single transaction, INSERT into `entries` with
    `user_id = current_user.id`, copying transcript/summary/key_points/todos/created_at,
    then DELETE source rows from `anonymous_demo_entries` and their MinIO blobs. Return
    `{ claimed: N, entry_ids: [...] }`.
  - **Idempotent:** calling twice with the same `demo_session_id` returns `{ claimed: 0 }`
    on the second call. Cookie cleared client-side on first success.
- Flywheel: after 2+ anonymous recordings under the same `demo_session_id`, the
  `/submit` response includes a `teaser` field when a repeated stem is detected.
  **Detection is deliberately lightweight — tokenize + lowercase + Porter-stem + stopword
  filter over the combined transcripts, NO LLM call.** If any stem appears ≥2 times
  across ≥2 different entries, return it as the teaser. Copy: "You've mentioned
  `{stem}` in 2 debriefs — sign in to see the pattern across your week." This is
  explicitly NOT the weekly-audit pipeline.
- Analytics: PostHog client + backend event emission tied by `demo_session_id`. Events:
  `landing_viewed`, `mic_tapped`, `recording_started`, `recording_completed`,
  `debrief_shown`, `teaser_shown`, `save_clicked`, `signup_completed`,
  `demo_claim_succeeded`, `demo_claim_missing`, `cookie_blocked`.
- Mobile-first: layout authored for 375px first, mic 120px+ tap target, sticky auth
  footer with safe-area-inset padding, keyboard-safe.
- /welcome post-OAuth route: reads the cookie, calls `/claim-demo-session`, shows "Your
  debrief is saved." + the entry, one-click "See all my entries" → /recording.
- Feature flags: `PUBLIC_DEMO_ENABLED` (master), `FLYWHEEL_ENABLED`, `WELCOME_HANDOFF_ENABLED`.

### Mic Button — Anti-Slop Lock-In

DESIGN.md forbids "glossy AI aesthetic." The mic is the single biggest trap. Lock
these visual rules:

| State | Visual |
|---|---|
| Idle | Flat cream fill (`palette.background`), 1.5px vermilion (`palette.accent`) hairline border, vermilion glyph, no shadow, no glow, no gradient. Subtle opacity pulse 0.92 ↔ 1.0 over 2.4s ease-in-out. |
| Recording | Flat vermilion fill (`palette.accent`), cream glyph (`#F5EDE0`). Inner-ring pulse 0.85 ↔ 1.0 over 0.9s. No outer glow. |
| Processing | Flat cream fill, animated hairline ring sweep (single segment, 1.2s linear rotation). Glyph replaced with "…" in DM Sans. |
| Mic-denied | Flat cream fill, muted rule (`palette.rule`) border, grey glyph. Caption below: "Enable mic in browser settings ↗" |
| `prefers-reduced-motion` | All pulses/rings disabled. Processing state uses static dashed border. |

Never: gradient fills, box-shadow glows, animated waveforms (idle OR recording —
we don't listen before you tap; lying about that is slop), frequency-responsive
visualization, Lottie animations.

## Latency model (real numbers, not vision copy)

The "8-second debrief" aspirational line is NOT a hard SLA. Realistic budget:
- Browser upload to MinIO (3–8 MB audio @ 30s): ~0.5–2s
- Whisper transcription (30s audio): ~2–5s
- GPT-4o-mini summarization (transcript → summary + key_points + todos, one call): ~1–3s
- Total p50: ~4–8s, p95: ~12s.

**Handling the wait is a feature, not an afterthought.** While the pipeline runs, the
fake "What your debrief looks like" strip is already visible below the mic. The real
output animates into place when ready, replacing the skeleton. No spinner. Progress
chip ("Transcribing… Summarizing…") optional, keep minimal.

## Critical error handling

- **Whisper empty transcript** (silent/garbled audio): backend must check
  `len(transcript.strip()) < 5` and short-circuit before calling GPT. Return `{"error":
  "no_speech_detected"}`; frontend shows "We couldn't hear you — try again."
- **GPT malformed JSON:** retry once with stricter schema prompt; if second fails, return
  the fake capped output with banner.
- **Cookie blocked** (Safari ITP, user-disabled): frontend set+read test on first mic
  tap. If fails, degrade to single-recording session (no teaser, no save across reload)
  and show an inline note "Enable cookies to record more than once."

## Revisions — Supersedes earlier sections where they conflict

This section is the authoritative backend/security spec. It reflects
/plan-eng-review (2026-04-24) + /codex plan review (2026-04-24). Where it
contradicts the earlier "Accepted Scope" or "Merge flow" sections, this wins.

### Schema: shared tables, no separate `anonymous_demo_entries`

Reuse existing `entries` + `entry_classifications` with migration-added columns.
There is NO `anonymous_demo_entries` table; the earlier `summary`/`key_points`/
`todos` JSONB shape does NOT exist.

Migration (single additive alembic revision):
- `ALTER TABLE entries ALTER COLUMN user_id DROP NOT NULL`
- `ALTER TABLE entries ADD COLUMN demo_session_id VARCHAR(64) NULL`
- `ALTER TABLE entries ADD COLUMN expires_at TIMESTAMPTZ NULL`
- `CREATE INDEX ix_entries_demo_session_id ON entries (demo_session_id) WHERE demo_session_id IS NOT NULL`
- `CREATE INDEX ix_entries_expires_at_demo ON entries (expires_at) WHERE demo_session_id IS NOT NULL`
- `ALTER TABLE jobs ALTER COLUMN user_id DROP NOT NULL`
- `ALTER TABLE jobs ADD COLUMN demo_session_id VARCHAR(64) NULL` + index
- `CREATE TABLE demo_cost_counter (date DATE PRIMARY KEY, cost_usd NUMERIC(10,4), updated_at TIMESTAMPTZ)`
- `CREATE TABLE demo_request_log (...)` as previously spec'd

**Query audit (in scope for this PR):** grep every `Entry` / `EntryClassification`
query; confirm each either filters by `user_id == current_user.id` (safe: NULL ≠ int)
or explicitly filters `user_id IS NOT NULL`. Document the audit result in the PR.

**Summary is mechanical**, not stored. Derived from classifications at read-time:
`"You spoke about {top 2-3 category nouns} — {N} todo(s), {M} key point(s)."` No
new LLM call, no new prompt, no eval suite.

### Pipeline: async + poll, reuse worker

`/v1/public/demo/submit` does NOT run Whisper/GPT inline. It:
1. Verifies Turnstile permit token (see "Turnstile flow" below).
2. Checks cost-cap read-only (no increment).
3. Calls `queue.enqueue(db, entry_id, user_id=None, demo_session_id=...)` — the
   existing worker picks it up.
4. Returns `{ entry_id, job_id }` immediately.

The existing `worker._process_job` handles both authed and anonymous jobs. Only
delta inside the worker: (a) skip notification push if `job.user_id is None`,
(b) if `job.demo_session_id` is set and this is the 2nd+ entry for the session,
call `teaser.compute_teaser` at the end and write the result to `EntryMetadata`
with key `demo_teaser`, (c) after Whisper succeeds, atomically debit real cost
via `SELECT ... FOR UPDATE` on `demo_cost_counter` for today's UTC date.

Frontend polls `GET /v1/public/demo/status/{entry_id}`. That endpoint reads the
server-side session cookie (see below), verifies `entry.demo_session_id` matches,
returns the Job step + classifications + `demo_teaser` metadata when done.

### Cost cap: check-at-submit, debit-at-use

- `/submit` does a READ-ONLY check: `SELECT cost_usd FROM demo_cost_counter
  WHERE date = today`. If `cost_usd >= cap`, return `{ "demo": "capped",
  "fake_output": {...} }`; do NOT enqueue.
- Worker, post-Whisper, computes actual cost from Whisper usage (seconds × rate)
  + GPT usage (input/output tokens × rate). Opens a transaction, `SELECT ... FOR
  UPDATE`, `UPDATE demo_cost_counter SET cost_usd = cost_usd + actual WHERE
  date = today`, commits.
- **Overshoot window:** because N requests can pass the check before any debits,
  actual daily cost can exceed cap by up to N × per-request cost (at current
  rate limit: 5 req/min worst case = ~$0.50 over cap). Acceptable. Set the env
  cap 10% under the true budget to absorb this.

### Atomicity: DB first, blob cleanup via sweep

**Claim endpoint** does a single Postgres transaction: `UPDATE entries SET
user_id = ?, demo_session_id = NULL, expires_at = NULL WHERE demo_session_id = ?
AND user_id IS NULL` + same for `jobs`. No blob operation happens inside this
transaction — the blobs were promoted implicitly because they're referenced by
`entries.raw_audio_key` and the row is now owned by the user.

**Sweep job** is intentionally two-step and idempotent: (1) SELECT expired rows,
(2) DELETE S3 blobs for their `raw_audio_key`s (ignoring 404), (3) DELETE rows
(CASCADE kills classifications + metadata + jobs). Partial failure is safe: if
step 2 crashes, rows remain and next sweep retries blob delete. If step 3 crashes
after step 2, orphan rows with missing blobs are deleted next run (downloading
would 404, which is fine — the row is being deleted anyway).

### Session identity: HttpOnly cookie + HMAC claim token

**Hijack fix (Codex P1 #1):** the `tlg_demo_sid` cookie becomes `HttpOnly`
(reversing the earlier decision). JavaScript cannot read it, so an XSS or a
leaked session_id cannot be used to claim another visitor's entries.

Frontend does not need the session_id for analytics — PostHog can use its own
distinct_id, correlated on the server side in the event payload.

**Claim flow:**
- `/v1/public/demo/presign` sets `tlg_demo_sid` (HttpOnly, SameSite=Lax, Secure,
  Max-Age=86400). Also returns a `claim_token` in the response body: HMAC-SHA256
  signed `(session_id, exp=created_at+24h)` using env `DEMO_CLAIM_HMAC_SECRET`.
- Frontend stores `claim_token` in `sessionStorage` (survives tab but not close;
  close-reopen requires a fresh session anyway).
- On "Save with Google": frontend passes `claim_token` to Supabase OAuth as a
  `state` param (URL-encoded, Supabase roundtrips it back).
- `/welcome` receives `state` from the URL, POSTs to `/v1/entries/claim-demo-session`
  with body `{ claim_token }` under the new user's JWT.
- Claim endpoint verifies HMAC + expiry, extracts `session_id`, runs the UPDATE
  from "Atomicity" section. Idempotent.

This dual path (HttpOnly cookie OR claim_token) solves Codex P1 #1 AND the
cookie-blocked P2 #10 simultaneously: if cookies are blocked entirely, the
claim_token carries identity through OAuth state.

### iOS Safari audio MIME (Codex P1 #3)

Do NOT pin `audio/webm`. iOS Safari records as `audio/mp4` (or `audio/m4a`);
Chrome/Firefox use `audio/webm`. Accept the set:

- Frontend: use `MediaRecorder.isTypeSupported('audio/webm;codecs=opus')` then
  fall back to `audio/mp4` on Safari. Pass the browser-reported `mimeType` to
  `/presign` as the `contentType` parameter (existing
  `services/storage.generate_presigned_put(key, content_type)` already accepts
  it — no change needed there).
- Backend: `/presign` validates the contentType is one of
  `{audio/webm, audio/mp4, audio/m4a, audio/mpeg}` and reflects it into the
  presigned URL. Reject anything else with 400.
- Whisper auto-detects format from file bytes; no backend code change for
  transcription.
- S3 object key extension matches the MIME: `.webm`, `.mp4`, `.m4a`.

Tested in Cypress on Safari + iOS Safari as part of the cookie-persistence
smoke test.

### IP identification for rate limits (Codex P1 #7)

Do NOT trust raw `X-Forwarded-For`. The backend is deployed on Render behind
Cloudflare (frontend on Cloudflare Pages, backend proxied). Extract IP via:

1. `CF-Connecting-IP` header if request has `CF-Ray` header (confirms it came
   from Cloudflare).
2. If no `CF-Ray`: fall back to Render's `X-Forwarded-For` last hop (split on
   comma, take the rightmost).
3. Reject requests that have neither `CF-Ray` nor a Render proxy signature.

Hash the resulting IP with `SHA256(ip + env DEMO_IP_HASH_SALT)` for logging and
rate-limit keys. Rotate salt quarterly (documented operational task).

### Turnstile flow — single challenge (Codex P2 #8)

User solves Turnstile ONCE, on the landing (not per-recording).

- Turnstile widget loads after first mic tap. User solves the challenge.
- Frontend POSTs `/v1/public/demo/verify-turnstile { token }`. Backend verifies
  with Cloudflare, returns `{ permit_token }` = HMAC-signed `(session_id, exp=+1h)`.
- `/presign` and `/submit` BOTH require the `permit_token` (header or body).
  Backend verifies HMAC. Expires after 1h or after 5 successful submits.
- After expiry, frontend re-challenges Turnstile inline.

This avoids the double-challenge / replay problem and keeps the friction to one
widget interaction per hour.

### Teaser safety filter (Codex P2 #11)

Porter stem alone surfaces garbage. Add these guards before returning a teaser:

- Min stem length: 4 characters.
- Lowercase-stem must match a top-5000 common English lemma allowlist (bundled
  as a static file in `services/teaser_allowlist.txt`, ~50KB).
- Blocklist (bundled `services/teaser_blocklist.txt`): profanity + first-name
  list (common 1000 English first names). These never surface as teasers.
- Non-English transcripts: if Whisper reports `language != 'en'`, skip teaser
  entirely for v1. Revisit for i18n.
- If no allowlisted stem repeats, teaser is null.
